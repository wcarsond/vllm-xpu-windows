The fast prompt-processing kernel hard-codes the 16x16x16 cooperative-matrix tile, which is what Nvidia offers. Xe offers 8x16x16, the backend found no match and silently ran the scalar fallback. The tile height is now a per-device specialization constant. test-backend-ops FLASH_ATTN_EXT: 5,297 of 5,297 against the CPU reference. KV slicing on top adds 13% at 16K and 16% at 32K; through the live server on a 15.8K-token prompt, 660 against 609 tok/s.

What was broken on Windows

Seven bugs, each found by measurement. The full investigation, wrong turns included, is PORT-NOTES.md in the repo

  1. long is 32 bits in SYCL device code under MSVC. Every cutlass-sycl flash-attention kernel killed the GPU context: the Xe copy atoms declared address builtins taking long, so every tensor base address reached the card with its top half cut off. Four headers changed to int64_t: from every kernel killing the card to 58 TFlop/s.
  2. No card-to-card peer access on WDDM: Intel's query_peer_access_wddm.cpp returns false unconditionally. Host memory is the channel, through a GPU-timeline all_reduce modelled on NCCL's LL protocol: each 8-byte unit carries 4 bytes of data and a 4-byte sequence tag, so a stale cache line fails its tag and is read again. 11 us against 258 us for the host-synchronous version it replaced.
  3. Windows renames are not atomic, so Triton's kernel cache races between ranks and one kills the other with PermissionError. One cache directory per rank. This hits any tensor-parallel setup on Windows, not only Intel.
  4. Unkillable zombie workers after every clean run: DLL unload handlers destroy a static SYCL device and the OpenCL runtime spins forever releasing its context. Workers now end with TerminateProcess.
  5. A GPU graph captured a host-memory collective, which recorded instead of ran. Graph capture is off for Windows with more than one card.
  6. Two tensor-parallel workers loading one checkpoint killed each other with 0xC0000005 at a different shard every run: tensor split fed the same page-cache pages to two adapters. One host memcpy per tensor before any card sees it. Four clean 72B loads in a row after, none before, and a cold start 40 s faster.
  7. Two processes each masked to its own card with ZE_AFFINITY_MASK fault on any concurrent host-to-device copy. Pick the card above the driver with ONEAPI_DEVICE_SELECTOR=level_zero:N.

Arc Pro B65 and B70

The B65 has the same 20 Xe cores as the B60, with 32 GB at 608 GB/s against the B60's 456 GB/s. Decode is bandwidth-bound, so read the decode numbers above as a floor for a two-B65 rig; prefill should land about where it is. That is an inference, not a measurement. The flash-attention fix should take the same path on both cards (same 8x16x16 tile); a shape listing or a bench from any other Intel GPU is the evidence still missing.
